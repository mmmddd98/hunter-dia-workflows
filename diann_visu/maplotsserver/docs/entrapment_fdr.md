# Entrapment FDR calculation

This page documents how the Entrapment FDR plots are calculated in the maplot server.

## Inputs

The plots start from the DIA-NN report rows after the selected search has finished. Internal DIA-NN decoys are kept separate from the `ENT_` entrapment proteins.

- `target`: a reported ID assigned to a non-ENT target protein.
- `ENT_`: a reported ID assigned to an entrapment protein generated by sequence shuffling.
- `DIA-NN decoy`: a row marked by DIA-NN as an internal decoy, usually `Decoy == 1`.

The empirical FDR shown in the plots is based on the `ENT_` entries, not on DIA-NN internal decoys.

## DIA-NN reported levels

In this mode the server uses entity definitions and q-value columns that DIA-NN reports.

| Level | Entity column | q-value column |
| --- | --- | --- |
| Precursor | `Precursor.Id` | `Q.Value` |
| Peptidoform | `Modified.Sequence` | `Peptidoform.Q.Value` |
| Peptide | `Stripped.Sequence` | best available row-level `Q.Value` |
| Protein group | `Protein.Group` | `PG.Q.Value` |

For each entity, the server keeps the best, smallest q-value observed for that entity. The selected threshold keeps entities where:

```text
entity_qvalue <= selected DIA-NN q-value threshold
```

## N-terminal evidence levels

In this mode the server uses the same biological entity definitions as the UpSet plots. These levels are made for N-terminal analyses and include the N-terminal status in the identity.

| Level | Entity identity |
| --- | --- |
| N-term precursor | `protein_id + peptide_start + stripped_sequence + nterm_status + charge` |
| N-term peptide | `protein_id + peptide_start + stripped_sequence + nterm_status` |
| N-term site | `protein_id + peptide_start + nterm_status` |
| N-term protein | `protein_id` |

DIA-NN does not report q-values directly for these custom N-terminal entities. Therefore the server assigns an entity q-value by taking the best row-level DIA-NN evidence:

```text
entity_qvalue = min(Q.Value of all DIA-NN rows belonging to this N-terminal entity)
```

This means the x-axis in the cumulative curve is still DIA-NN `Q.Value`, but the counted objects are the server's own N-terminal entities.

## Bar plot

The bar plot shows the empirical entrapment rate at the selected threshold:

```text
ENT_ / target
```

For each search, specificity group, and selected level, the server:

1. builds the entity IDs,
2. assigns each entity its best q-value,
3. keeps entities at or below the selected q-value threshold,
4. counts target entities and `ENT_` entities,
5. plots `ENT_ / target`.

## Cumulative curve

The cumulative curve shows the same idea across all DIA-NN `Q.Value` thresholds on the x-axis.

For each level and specificity group, entities are sorted by their entity q-value. Moving left to right, the server cumulatively counts:

```text
cum_target
cum_ENT
```

and plots:

```text
cumulative empirical FDR = cum_ENT / cum_target
```

The vertical line marks the selected DIA-NN q-value threshold used by the bar plot.

## Interpretation

For DIA-NN reported levels, the plot asks how well DIA-NN's own reported q-values correspond to empirical `ENT_` false discoveries at similar entity levels.

For N-terminal evidence levels, the plot asks a different and more project-specific question: after aggregating evidence into biologically relevant N-terminal entities, how many of those entities are supported by entrapment proteins at a given DIA-NN row-level `Q.Value` threshold?
